### 轮 2
- 学生：「我以为是 A。b=a 会复制出一个新的列表，内容跟 a 一样。所以 b 和 a 是两份，内存里应该有 2 个列表对象。但看运行结果又好像不是这样。」
- 助教【发给学生的话】：
「好，这里已经能确认了。先给你结论，再讲清楚。

**诊断结论：** 你把 `b = a` 理解成了"复制一份新列表"（A），但 Python 实际是 **B**——赋值只是给同一个东西再起一个名字，**不复制任何内容**。

**为什么：**

1. `a = [1, 2]` 这一步其实做了两件事：先在内存里创建了**一个**列表对象 `[1, 2]`，然后让名字 `a` 指向它。
2. `b = a` 不做复制，只是让名字 `b` 也**指向 a 已经指向的那个列表**。相当于给同一个列表贴了第二个标签。
3. 所以 a 和 b 是**同一个列表的两个名字**，内存里从头到尾只有 **1 个**列表对象（而不是你以为的 2 个）。
4. 列表是"可变"的，`b.append(3)` 是直接**在原地改动**那唯一一个列表。既然 a 也指向它，通过 a 看自然就变成 `[1, 2, 3]`。

**换个例子看（不复用你的题）：**

```

n = m
n.append(7)
```

`m = [5, 6]` 创建一个列表 → `n = m` 给这个列表再贴一个标签 "n" → `n.append(7)` 把那个列表改成 `[5, 6, 7]`。因为 m、n 指同一处，打印 `m` 会得到 `[5, 6, 7]`。


「这是个很好的追问，它确实是一个**新点**，值得单独讲清楚——`+` 和 `append` **不是一回事**。

关键区别：

- `+`（两个列表相加）会**拼出并返回一个全新的列表**，原来的列表一个字都不动。
- `y = y + [5]` 这句话其实是两步：先算出新列表 `[4, 5]`，再把它**重新赋值**回给 y，让 y 指向这个**新对象**。
- `append` 则是**原地修改**原来那个列表，对象还是同一个，不新建。

所以回到你问的例子：

- `x` 从头到尾都指着原来的 `[4]`，从没被改过 → `print(x)` 输出 `[4]`。
- `y` 最后指向了新列表 `[4, 5]` → `print(y)` 输出 `[4, 5]`。

一句话：`append` 是在**同一个列表上改**；`y = y + [5]` 是**造了一个新列表再让 y 指向它**。两者不同。
