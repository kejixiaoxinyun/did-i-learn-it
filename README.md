# 学会了吗（did-i-learn-it）

一个面向大学生的知识漏洞诊断与迁移验证 Skill。它不直接给答案，而是走完一个学习闭环：**诊断 → 定向讲解 → 独立验证 → 修复报告**，帮学生找到"到底哪里不会"，并检查这次学习是否真的有效。

## 它适合谁

- "上课能听懂，一做题就不会"的学生。
- "看答案都懂，自己动手就卡"的学生。
- 想知道自己到底卡在哪一步，而不是只想抄答案的学生。

目标适用于推理链清晰的数学、物理、计算机、经济学等科目；纯记忆内容不作为首版重点。v5已执行20场全量回归，当前复核为18通过、1需修复、1覆盖不足；不代表真人学习效果已经验证。

## 它做什么 / 不做什么

| 做什么 | 不做什么 |
|--------|----------|
| 通过追问定位五类知识漏洞（概念理解、前置缺失、方法选择、操作计算、迁移失败） | 不直接代做作业 |
| 只针对关键漏洞做最小化讲解 | 不系统讲授整章内容 |
| 生成新情境验证题，检验独立应用能力 | 不把"我懂了"当作学会 |
| 产出结构统一的学习修复报告 | 不虚构学生的错误和进度 |
| 判断失误时如实说明"暂无法判断" | 不跨会话记忆（每次学习以报告为界） |

## 快速上手

三种典型用法（触发词：学会了吗、知识漏洞、帮我诊断、听不懂、看懂答案但不会做题、验证掌握、学习修复报告）：

1. **描述卡点**："我不懂 XX 概念" / "这一步为什么这样" → 进入诊断。
2. **贴题目和你的做法**：附上题目、你的解答或错误答案 → 定位出错位置和原因。
3. **查看进度**："学会了吗？" / "给我学习报告" → 生成当前学习修复报告。

最佳实践：提供越多真实材料（题目、你的过程、你的答案、课件片段），诊断越准；材料不足时 Skill 会先追问。

## 在华为云码道中使用

1. 下载 [码道专用导入包](dist/did-i-learn-it-codearts.zip?raw=true)。包内含同名技能目录及六份运行文件，不包含评测答案或开发备份。
2. 码道桌面端进入“扩展 → 技能 → 上传技能”，选择 ZIP；安装后在“我安装的技能”中启用并用于新任务。
3. 码道 IDE 进入“设置 → 技能与规则 → 项目级或个人级 → 导入”，选择 ZIP；在智能体模式中通过 `/did-i-learn-it` 或明确写出技能名称调用。

依据：[码道桌面端技能文档](https://support.huaweicloud.com/usermanual-codeartsdesktop/desktop_0014.html)、[码道 IDE 技能文档](https://support.huaweicloud.com/usermanual-codeartsagent/codeartsagent_ug_0024.html)。不同客户端版本的入口可能不同；实际加载和真人效果仍需在目标客户端验证。

启动时提供真实题目、自己的过程及具体卡点，例如：

```text
使用 did-i-learn-it 技能，帮我诊断学习问题。
题目：……
我的解法：……
我不懂的地方：……
```

学生对话只加载 `SKILL.md`、`workflows/` 和 `references/`，不把 `evals/` 中的测试分支、评分或答案注入助教。运行日志中的本地文件路径是原测试环境的记录，复现时应使用自己的安装目录。

## 一次完整学习闭环的样子

以下为演示预期流程（非真实运行记录）：

1. 学生："lim(x→3) f(x)=5 我不理解，x=3 代进去不就行了吗？"
2. Skill 诊断：概念理解错误（把极限等同于该点函数值），证据 = 学生的表述，等级 = 已确认。
3. Skill 讲解：只用一个"接近但不等于"的小例子讲清"趋近 vs 到达"，并用一道小题确认理解。
4. Skill 出验证题：换一个新函数、新情境（如 f(x)=(x²-1)/(x-1)，问 x→1），请学生独立作答。
5. 学生独立作答正确 → 状态更新为"本次验证通过"。
6. Skill 输出学习修复报告：漏洞、证据、讲解、验证表现、掌握状态、下一步建议。

编程方向的预期示例：学生提供 Python 的 `a=[1,2]; b=a; b.append(3)`，不理解为什么 a 也变化 → 先问其如何理解 `b=a` → 学生明确说"会复制新列表"后，才确认赋值与复制的概念误解 → 针对性解释 → 换代码验证并要求理由。此示例同样不是实际运行记录。

## 已知限制

- **无跨会话记忆**：每次会话独立，学习历史只保留在修复报告中；带报告回来可恢复上下文。
- **验证通过 ≠ 长期掌握**：它只说明学生在当前这道新题上独立做对了。
- **诊断基于文本证据**：材料不足或不完整时，会先追问或如实标注"暂无法判断"，不猜。
- **无法保证讲解完全无错**：涉及具体学科细节时，Skill 被要求对不确定的内容明确标注"需要核实"。
- **运行环境要求**：宿主须能加载 Skill 指令并按相对路径读取资源；自动触发方式取决于平台。无外部工具依赖，码道/果办的实际加载及对话效果仍待验证。
- **图片输入**：直接贴题目截图需要平台具备图片识别能力；平台无多模态能力时，请先将题目转为文字再输入。

## 自测与质量评估

- `evals/test-cases.md` 内置 18 个案例，其中两例各有 A/B 分支，共 20 个执行场景；包含数学、Python、物理、经济学，以及拒绝验证、材料不全、连续未理解等边界。
- 重点检查"相同错误、不同原因"能否被区分，避免看到符号错误就断言粗心，也避免把正确但低效的方法误判为不会。
- 评分维度：诊断准确性、证据可靠性、讲解有效性、验证有效性、结果真实性。每项 0-2 分；未适用维度记 N/A，不能给满分。完整流程与边界流程分别汇总。
- **最新v5全量：20/20场已执行，18通过、1需修复、1覆盖不足。** T18停止行为正确，但中途引用两题常数时失准；T16简谐运动补题未给方案要求的公式。结果见 `evals/runs/_smoke-summary.md`，逐轮记录见 `evals/runs/full-v5-20261022-luna-max.md`。历史v3及v5定向成绩分别保留，不迁移或覆盖。
- 已设计普通问答、简短陪练提示词与完整 Skill 的三组对照，尚未运行；对照实验结果不能从单组回归成绩推断。
- 修改后须回归所有场景，保留实际逐轮记录；本轮使用冻结v5运行文件，未在测试中修改规则。主动补测、无效题和未完成尝试分别标注，不把模型模拟等同于真实教学效果。目标平台可用性和真实学习效果分别验证。
