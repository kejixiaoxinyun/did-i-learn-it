# 诊断工作流

目标：找到能解释当前问题的最小知识漏洞，并标注证据等级。不把所有潜在问题都列成学生的缺陷。

## 第一步：输入线索分析

按学生提供的材料类型提取线索：

| 学生提供 | 提取什么 |
|----------|----------|
| 概念描述 | 学生用自己的话如何定义；漏掉了哪些关键条件或前提 |
| 题目 + 最终答案（无过程）| 错误答案与正确答案的差异可能来自哪几类错误 |
| 完整解题过程 | 第一次偏离正确路径的位置；偏离点属于哪类错误 |
| 课件 / 笔记文本 | 学生已接触过什么表述，避免讲解时重复 |
| 已懂部分 + 卡点 | 明确边界：会什么、从哪一步开始不会 |

线索不足时才追问（追问规则见 SKILL.md 全局规则 2）。题目缺少必要条件时，先要求学生补全，不自行编造条件。

材料过长时（如整章课件、多页笔记）：先根据学生的问题定位与当前卡点相关的段落再分析，不全文展开；无法定位时，请学生指认与问题最相关的一两段。

## 第二步：假设排序

1. 从线索中列出能解释当前错误的假设，最多 3 个，每个标注现有证据是支持、反对还是无关。
2. 排序原则：能解释最多线索的优先；更基础（更前置）的优先。
3. 一次只主攻 1 个假设，最多 2 个；其余明确搁置，不要一起排查。

先记录可观察的事实，再推测原因。例如 `2x+3=11 → 2x=11+3` 能确认变形错误，但不能直接确认只是笔误；让学生解释等式两边应做什么操作，才能区分操作失误与概念缺失。学生说"公式我会"是线索，不能替代实际展示。

证据按具体题目去重：同一题的分步追问仍算一例。区分学生自述（如"不会""记不清"）、实际作答和未作答；自述不等于观察到的计算错误，未答不算失败。诊断、讲解和报告中的错误次数、作答表现及原因结论，都须逐项核对会话原话。回答仍有歧义或追问轮次用尽且没有可靠结论时，标为"尚无法判断"，不得强行判定为前置缺失（追问上限见 SKILL.md 全局规则 2）。

## 第三步：诊断问题设计

每个问题只针对一个假设，尽量让不同错误原因产生可区分的回答：

| 待区分假设 | 诊断问题模式 | 可区分的回答 |
|-----------|-------------|-------------|
| 概念理解 | 让学生用自己的话解释定义、条件或含义 | 表述与正确定义有实质出入 → 概念问题 |
| 前置缺失 | 单独考一个更基础的小问题 | 基础小问题答错 → 前置问题 |
| 方法选择 | 给一个小变式，问"这里用什么方法、为什么" | 能复述方法但选错或说不出理由 → 方法问题 |
| 操作计算 | 让学生重算出错的某一步，或问"这一步怎么得到的" | 思路对、局部算错 → 操作问题 |
| 迁移失败 | 给一个只改变情境或表述的小题 | 熟悉题型会做、换表述就卡 → 迁移问题 |

要求：问题要短，一次最多 1-2 个；不把诊断变成连续小测验。

## 第四步：根据回答更新诊断

- 学生回答与原假设冲突时，更新判断，不机械重复原有结论。
- 被推翻的假设明确记录"已排除（原因）"。
- 学生回答有歧义时，先确认学生的意思再下结论，不猜测。

## 第五步：输出诊断结论

格式：

```
主要漏洞：〈类型〉〈具体内容〉
证据：〈学生的原话 / 关键回答 / 出错位置，引用具体内容〉
证据等级：已确认 / 最可能 / 尚无法判断
已排除：〈假设〉（原因），如无则省略
次要漏洞（暂缓）：〈已发现但本次不处理的漏洞及原因，如无则省略〉
下一步：进入讲解 / 继续收集证据（差什么）/ 说明为什么暂时无法判断
```

证据等级定义：
- 已确认：学生的明确解释或区分性作答足以支持该原因，并排除当前主要竞争假设；只确认错误位置时不得提升原因的证据等级。
- 最可能：多条线索一致，但没有直接证据。
- 尚无法判断：回答缺失、歧义或信息不足。此时如实告知学生还需要什么信息。

五类错误的定义、典型表现与区分细节见 references/error-types.md。
