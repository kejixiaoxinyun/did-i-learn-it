# 迁移验证工作流

目标：检验学生能否把刚学的内容应用到新情境，而不是复述讲解内容。

## 验证题设计要求

1. 与原题考查**相同的核心知识**（即刚讲过的漏洞点）。
2. 在数值、条件、表达方式或问题情境上至少有一处**实质变化**。
3. **不照搬**讲解中出现过的例子、数字和答案结构。
4. 难度适当：不引入与本次漏洞无关的新知识，避免无关干扰。
5. 出题时先写好**预期答案和评分标准**（列出关键步骤给分点），并按 SKILL.md 全局规则 4 检查题目条件是否充分。

出题自检：验证题必须让刚讲的漏洞点成为正确作答的**必经点**——概念 / 方法 / 迁移类漏洞，指解题必须用到刚讲的判断或知识；操作 / 计算类漏洞，指正确作答必须避开刚讲的易错点（如必须正确移项变号）。如果学生不运用刚讲的内容也能做对 → 验证无效，重新出题。

## 验证流程

1. **呈现题目**：明确请学生独立作答（提醒不看之前的讲解），不同时展示答案。
2. **等待独立作答**：学生拒绝作答或暂停时，记录"未验证"，状态保持"待验证"，不计失败或验证轮次。若提供过针对该验证题的关键提示或答案，该题只能算辅助练习；愿意继续时另出新题独立验证。
3. **按预设标准评价**：检查最终答案 + 推理过程 + 关键条件的使用，不只看答案对错。
4. **判断错误性质**：是原有漏洞未解决，还是出现了新问题。
5. **结果分支**：
   - 达到预设标准 → 状态 = 本次验证通过。
   - 未通过且原有漏洞仍在 → 回讲解工作流补讲，之后生成**新的**验证题（不重复用过的题）。
   - 未通过且出现新漏洞 → 先回诊断工作流处理新漏洞。
   - 轮次用尽（累计 3 轮验证）仍未通过 → 如实报告"仍需练习"，在报告中给出针对性练习建议。

轮次计数：学生对一道有效验证任务实际独立作答才计 1 轮（含前置题 + 主线题的多级验证合计 1 轮）；补讲后新题的独立作答计新一轮。未作答、辅助练习及确认有误的题目不计轮次。

## 掌握状态判定

| 状态 | 判定条件 |
|------|----------|
| 待诊断 | 没有足够证据支撑任何诊断结论 |
| 待修复 | 诊断已确认漏洞，但讲解未完成 |
| 待验证 | 理解确认通过，尚未完成独立验证，包括拒绝或暂停作答 |
| 本次验证通过 | 学生独立作答达到预设评分标准 |
| 仍需练习 | 独立作答未达标，或验证轮次用尽仍未通过 |
| 暂无法判断 | 已提交的作答有歧义、只有无法支持评价的答案，或题目及证据不足；单纯未开始验证保持待验证 |

硬规则：

- 学生说"我懂了""明白了"不是验证通过的依据，必须以独立作答为准。
- 学生复述讲解内容不等于迁移验证通过；必须换情境作答。
- 已明确提示方法或关键结构的题目仅作辅助练习，不能用于证明独立选法；回做原题属于回练，不能计为新情境迁移验证。需要补验时另换未提示的新题。
- 验证通过只描述本次任务中的表现；报告和后续对话中不得写成"已掌握"或"永久掌握"。
- 评价时区分：原有漏洞未解决（回补讲）与新出现问题（回诊断）。
- 学生质疑验证题本身有误（题目歧义、条件矛盾、疑似无解）时：先核对题目，确有误则明确承认并更换一道新验证题，不把出题错误计入学生失败。
- 学生多次未通过时，先指出其已取得的进展（如"方法已经选对了"），再给练习建议；不使用贬低性表述，不把失败等同于能力不足。

## 输出

- 验证前仅向学生展示题目及必要条件；与原题的差异点、解题方法和评分点留到评价或报告时说明，避免提前提示考点。
- 预设评分标准（出题时确定，评价前不向学生展示）。
- 学生实际表现（如实记录答案与关键错误）。
- 更新后的掌握状态 + 判定理由。
