# 定向讲解工作流

目标：只解决已发现或正在确认的关键漏洞。讲解质量不看长度，看学生能否因此独立做对新题。

## 讲解流程（六步）

1. **对齐现状**：用简单语言指出学生卡在哪一步、为什么卡（引用学生自己的过程或回答）。
2. **补缺口**：只解释缺的那块概念或规则，不重讲学生已掌握的内容。
3. **小例子**：给一个短小、针对性强的例子；不复用学生的原题。
4. **展示推理**：给出必要推理步骤，并解释每一步为什么这样做。
5. **理解确认**：出一道与例子不同的简短问题，确认学生是否真的理解；按 SKILL.md 全局规则 4 检查题目条件是否足以支持预期判断。
6. **分支**：
   - 确认通过 → 进入验证工作流（workflows/verify.md）。
   - 确认未通过 → 换一种方式再讲一次（换角度、换例子）。
   - 换方式后仍未通过 → 在 SKILL.md 的累计轮次上限内回到诊断工作流，检查是否存在更前置的漏洞；达到上限则出报告，不循环重来。

两次讲解未通过不是自动结束条件。学生未要求停止、讲解额度仍有剩余时，按上述分支继续；若诊断追问额度已用尽但原诊断有可靠证据，可在剩余讲解额度内换角度确认；若仍没有可靠诊断，则如实报告“暂无法判断”，不强行补讲。返回诊断不重置讲解或验证计数。

讲解额度用尽时，依据实际证据收尾：仍有已观察到的错误则报告“仍需练习”，证据不足则“暂无法判断”，不用中途阶段的“待修复”作为额度耗尽的结论。未回答的确认题仍记未作答，不补判失败。

## 按错误类型选讲解策略

| 错误类型 | 讲解策略 |
|----------|----------|
| 概念理解错误 | 让学生先说出自己的理解 → 指出与正确定义的具体差异 → 强调被漏掉的关键条件或前提 |
| 前置知识缺失 | 暂停主问题 → 补最小必要的前置基础 → 前置确认通过后再回到主问题 |
| 方法选择错误 | 给出"何时用 / 为何用"的判断依据 → 用两个对比情境让学生练习方法选择 |
| 操作或计算错误 | 定位具体出错步骤 → 讲该步骤的易错点 → 让学生自己重算这一步，不代算 |
| 知识迁移失败 | 显式对比原题与新情境：什么变了、什么没变 → 总结可迁移的判断标准，而不是再讲一遍知识点 |

发现多个漏洞时，一次只讲一个主要漏洞；次要漏洞记入报告"尚未解决的问题"。

## 讲解原则

- 一次一个主要漏洞；发现前置知识缺失时，先补齐必要基础再回主线。
- 不重复学生已经掌握的内容。
- 不以讲解长度衡量教学质量；讲透关键一步胜过完整复述整章。
- 学生暂时答错不等于能力不足，只说明这个知识点还没通。
- 讲解内容必须准确；不确定的细节明确说"需要核实"，不编造。
- 方法选择要说明适用条件并给一个对比情境，避免把表面特征当作通用规律。例如乘积形式不意味着必须分部积分；先检查直接积分、代数化简、换元或分部能否简化问题。“没有明显内函数及其导数”不推出“应当分部”，例如 ∫x(x+1)dx 可先展开。选法线索必须保留适用条件。

## 输出

- 已讲解的漏洞及要点。
- 理解确认题与学生回答。
- 结论：通过（进入验证）/ 需继续讲解 / 疑似更前置的漏洞（回到诊断）。
